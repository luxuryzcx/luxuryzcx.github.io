1. Jackson：JSON 界的“超级管家”

Jackson 是 Java 中处理 JSON 最流行的工具。它的核心逻辑是：你给我一串 JSON 文本，我就能把它还原成对应的 Java 对象。

  • 为什么它“危险”？

    它有一个功能叫“多态类型处理”（Polymorphism）。为了方便开发，Jackson 允许你在 JSON 里通过 @type 字段直接告诉它：“请帮我实例化这个类。”

    • 正常情况：{"name": "张三"} -> Jackson 创建一个“用户”对象。

    • 攻击情况：{"@type": "com.evil.HackClass"} -> Jackson 看到 @type，会说：“没问题，管家这就去给你实例化一个 HackClass 对象。”

    • 后果：如果 HackClass 的构造函数或 setter 方法里有恶意代码（比如执行命令），Jackson 就会在不知情的情况下帮攻击者把“定时炸弹”给装好了。

2. XStream：XML 界的“乐高大师”

XStream 和 Jackson 很像，只不过它处理的是 XML。它有一个更底层的机制叫 Converter (转换器)。

  • 它是怎么工作的？

    XStream 维护了一套“转换策略”。当你给它一个 XML 时，它会根据标签名去匹配对应的“转换器”，然后由这个转换器去调用 Java 的 API，把 XML 里的数据填进对象里。

  • 为什么它“危险”？

    XStream 的转换器实在太多了，而且功能太强了。

    • 攻击手法：攻击者构造一个特殊的 XML，让 XStream 触发一个并不应该在这个场景下使用的转换器。

    • 举例：如果攻击者让 XStream 去处理一个具有“动态代理”能力的转换器，XStream 就会通过反射去调用系统里的各种方法，最终把程序“拐”到执行系统命令的路上去。

3. 为什么它们是“漏洞挖掘”的重点？

简单来说，是因为“它们太听话、太智能了”。

  1. 自动化程度高：它们不需要你写代码去一个个赋值，只要你给它数据，它就敢自动帮你创建对象、给属性赋值、调用方法。

  2. 权限过大：在反序列化过程中，它们几乎可以操控程序里的任何类（只要该类在 classpath 里）。

  3. 开发者的疏忽：很多开发者在使用 Jackson 或 XStream 时，直接使用了“默认配置”。默认配置通常是最不安全的，因为它开启了所有功能。
